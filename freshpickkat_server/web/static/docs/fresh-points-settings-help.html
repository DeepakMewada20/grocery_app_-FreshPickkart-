FreshPoints Settings — Complete Field Reference

Detailed explanation of every FreshPoints setting with examples. Use this guide to configure the points loyalty program correctly.

Table of Contents 1. General 2. Redemption Rules 3. Point Expiry 4. Admin Controls 5. Pricing Calculation Flow

1. General

Editable
isEnabled
Type: Boolean  |  Default: true
Master switch for the entire FreshPoints loyalty system. When false:
  • Users cannot earn or redeem points
  • The FreshPoints section is hidden at checkout
  • All point-related pricing steps are skipped
  • Existing points are preserved (not deleted)
Example: Set to false temporarily during a system migration. Users see no points option at checkout, but their balances are safe.

2. Redemption Rules

Editable

These settings control how and when users can redeem their FreshPoints.

redemptionPercentageLimit
Type: Double (Percentage)  |  Default: 50.0
The maximum percentage of the payable amount that can be paid using FreshPoints.

Formula:
maxRedeemable = (payableAmount × redemptionPercentageLimit / 100)

For example, at 50%, if the payable amount is ₹200, the user can redeem at most ₹100 worth of points (100 points). The remaining ₹100 must be paid with cash/UPI.

The user's current point balance is also a limiting factor — the actual redeemable amount is the lower of the limit and their balance.
Example 1: 50% limit, ₹400 payable, user has 500 points balance:
max redeemable = min(400 × 50%, 500) = min(200, 500) = 200 points (₹200)

Example 2: 25% limit, ₹400 payable, user has 500 points:
max redeemable = min(400 × 25%, 500) = min(100, 500) = 100 points (₹100)

Example 3: Same 50% limit, ₹400 payable, but user has only 60 points:
max redeemable = min(200, 60) = 60 points (₹60)
minimumOrderForRedemption
Type: Double (₹)  |  Default: 0.0
The minimum order payable amount (after coupons, before FreshPoints discount) required for the user to be able to redeem points. Set to 0 to disable — any amount qualifies.

This acts as a floor. If the payable amount is less than this value, the user cannot redeem any points, even if they have a large balance.
Example: minimumOrderForRedemption = 100
Cart total = ₹250, coupon discount = ₹160 → payable = ₹90
90 < 100 → ❌ Cannot redeem points

With same setting, cart total = ₹300, coupon discount = ₹100 → payable = ₹200
200 ≥ 100 → ✅ Can redeem points (up to 50% = 100 points)
allowRedemptionOnCOD
Type: Boolean  |  Default: true
Controls whether users can redeem FreshPoints on Cash on Delivery (COD) orders. When false, the FreshPoints option is hidden at checkout if the user selects COD as their payment method.

This is useful if you want to encourage prepaid orders, since COD has higher operational costs and more cancellations.
Example: false → User with 500 points selects COD at checkout. FreshPoints slider is hidden. User must pay the full amount in cash.

If the same user selects UPI/online payment, they can redeem points as usual.

3. Point Expiry

Editable
enablePointExpiry
Type: Boolean  |  Default: false
When true, points expire after pointExpiryDays days from the date they were earned. A cron job runs periodically to expire old points.

Point expiry works per-transaction: each earning transaction has its own expiry date. So if a user earns 50 points today and 50 points next week, the first 50 expire separately.
Example: true with pointExpiryDays = 90
User earns 50 points on 1 Jan → points expire on 1 Apr.
User earns another 50 points on 15 Jan → those expire on 15 Apr.
pointExpiryDays
Type: Integer  |  Default: 365
Number of days after which earned points expire. Only applies when enablePointExpiry is true. The count starts from the date each point was credited.
Example: 365 → Points earned today are valid for 1 year. After 365 days, the points are automatically deducted from the user's balance.

4. Admin Controls

Editable
enableAdminAdjustments
Type: Boolean  |  Default: true
When true, admins can manually add or deduct FreshPoints from any user's account. This is useful for:
  • Manual rewards for special promotions
  • Correcting point balances due to system errors
  • Deducting points when a reward is reversed (referral fraud)
When false, the "Adjust FreshPoints" button is hidden from the admin dashboard.
Example: true → Admin opens Referral Dashboard → taps "Adjust FreshPoints" → searches for a user → adds 100 points with reason "Customer satisfaction bonus" → points credited immediately.

5. Pricing Calculation Flow

Understanding how FreshPoints interact with other pricing steps.

Order Pricing Steps (in order): │ ├── 1. Product Subtotal (price × qty) ├── 2. BOGO discount ├── 3. Combo discount ├── 4. Coupon discount (best coupon auto-applied) ├── 5. Reward discount (SMGM) ├── 6. FreshPoints discount ← HERE │ ├── isEnabled check │ ├── payable ≥ minimumOrderForRedemption check │ ├── allowRedemptionOnCOD check (if COD) │ ├── maxRedeemable = (payable × redemptionPercentageLimit / 100) │ ├── actual = min(maxRedeemable, userBalance, userInput) │ ├── deduct points from user balance │ └── finalAmount -= actual ├── 7. Delivery fee added └── 8. Final amount = amount to pay
💡 Key Point: FreshPoints are applied after coupons but before delivery fee. This means the percentage limit is calculated on the payable amount after coupon discounts, giving the user a fair redemption value. The delivery fee is added at the end, so the user saves on the product cost but not on delivery (by design — to prevent abuse).
Complete Example:
Product price: ₹500
Coupon discount: -₹100 (20% off)
Payable after coupon: ₹400
FreshPoints settings: 50% limit, minimum order ₹50, allow COD
User balance: 300 points

Step 1: payable (₹400) ≥ minimumOrderForRedemption (₹50) → ✅
Step 2: maxRedeemable = 400 × 50% = 200 points
Step 3: actual = min(200, 300) = 200 points → -₹200
Step 4: payable after FP = ₹400 - ₹200 = ₹200
Step 5: delivery fee = ₹40
Step 6: final amount = ₹240

Redemption Formula Summary

Step Formula / Logic
1. Minimum order check if (payable < minimumOrderForRedemption) → return 0
2. Percentage cap maxByLimit = floor(payable × redemptionPercentageLimit ÷ 100)
3. Balance cap maxRedeemable = min(maxByLimit, userBalance)
4. User input clamp actual = clamp(userInput, 0, maxRedeemable)
5. Result freshPointsDiscount = actual
finalPayable = payable − actual + deliveryFee

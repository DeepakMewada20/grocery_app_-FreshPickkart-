Referral Settings — Complete Field Reference

Detailed explanation of every setting field with examples. Use this guide to configure the referral program correctly.

1. General

Editable
isEnabled
Type: Boolean  |  Default: true
Master switch for the entire referral reward system. When false, checkOrderForReward() returns immediately — no rewards are processed. Referral code application during signup still works.
Example: Set to false during a promotion freeze. Existing referrals stay in their current state, no new rewards are issued.

2. Invitee Coupon

Editable

The person who was referred (invitee) gets a coupon instantly when they sign up with a referral code.

inviteeCouponEnabled
Type: Boolean  |  Default: true
If enabled, a coupon is created and assigned to the invitee during reward processing.
Example: true → invitee gets ₹50 off coupon. false → no coupon issued.
inviteeCouponAmount
Type: Double  |  Default: 50.0
Discount value of the coupon. Applied as a flat discount on the invitee's next order.
Example: 100.0 → invitee gets a ₹100 OFF coupon with code WELCOMEFPKAB12.
inviteeCouponCodeTemplate
Type: String  |  Default: "WELCOME{CODE}"
Template for the coupon code. {CODE} is replaced with the actual referral code used.
Example: Template "WELCOME{CODE}" with referral code FPKAB12 → coupon code = WELCOMEFPKAB12.
inviteeCouponMinOrderAmount
Type: Double  |  Default: 199.0
Minimum cart subtotal (after other discounts) required for the referral coupon to be applied. If the cart total is below this amount, the coupon will not auto-apply during checkout.
Example: 199.0 → cart must be ₹199+ for the WELCOME coupon to apply. A ₹150 cart would NOT get the coupon discount.
inviteeCouponValidityDays
Type: Integer  |  Default: 15
Number of days the referral coupon remains valid from the moment it is created. After this period, the coupon expires and cannot be used.
Example: 15 → Coupon created on 1 Jan → expires on 16 Jan. The invitee must place their first order within 15 days to use the coupon.

3. Referrer Rewards

Editable

The person who shared the referral code (referrer) earns FreshPoints.

referrerPointsEnabled
Type: Boolean  |  Default: true
If enabled, the referrer earns FreshPoints when a referral qualifies.
referrerRewardPoints
Type: Integer  |  Default: 50
Number of FreshPoints awarded per successful referral.
Example: 50 → referrer gets 50 FreshPoints. 1 FreshPoint = ₹1. After 10 referrals, the referrer has 500 points (₹500 value).

4. Qualification Rules

Editable

Conditions an order must meet to trigger the referral reward.

rewardTriggerStatus
Type: Dropdown  |  Default: "DELIVERED"
The minimum order status required to trigger reward evaluation. When the order reaches this status, checkOrderForReward() runs.
Options (in order): PLACED → CONFIRMED → PACKED → OUT_FOR_DELIVERY → DELIVERED. If set to OUT_FOR_DELIVERY, reward triggers when the order goes out for delivery (no need to wait for delivery confirmation).
maxRewardedPerMonth
Type: Integer  |  Default: 20
Maximum number of rewarded referrals a single referrer can have per calendar month. Counts from the 1st of the month UTC. Set to 0 to disable.
Example: 5 → Referrer A can earn rewards for max 5 referrals per month. After 5 rewards in January, all further qualified referrals in January are silently skipped. Resets on 1st February.

5. Expiry & Fraud

Editable
enableReferralExpiry
Type: Boolean  |  Default: false
If enabled, old SIGNED_UP referrals (invitee signed up but never ordered) are automatically expired after referralExpiryDays. A cron job runs every 24 hours to check and expire.
Example: true + referralExpiryDays = 30 → A referral where the invitee signed up 31 days ago with no order → status changes to EXPIRED.
referralExpiryDays
Type: Integer  |  Default: 90
Number of days after which a SIGNED_UP referral expires. Only used if enableReferralExpiry is true.
enableFraudProtection
Type: Boolean  |  Default: true
Master gate for the fraud scoring engine. When true, the referral goes through the full scoring pipeline (hard reject rules + soft scoring rules). When false, fraud scoring is completely bypassed and the reward is processed directly.
Example: false → every qualified referral is auto-approved without any fraud check. Use only during testing or for trusted user groups.

6. Qualification Hardening

Editable
minimumActualPaymentForQualification
Type: Double  |  Default: 0.0
Minimum actual payment (cash/UPI paid) required for the referral reward to trigger. Set to 0 to disable (any payment amount qualifies). This prevents fake referrals with very low-value orders from earning a reward.
Example: Order ₹500 with ₹450 coupon → finalAmount = ₹50. minimumActualPaymentForQualification = 100 → FAIL. User actually paid only ₹50, which is below the ₹100 floor.
maxRewardedPerDay
Type: Integer  |  Default: 3
Maximum rewarded referrals per referrer per day (UTC). Prevents a single user from gaming the system with many referrals in one day.
Example: 3 → Referrer A gets 3 referrals rewarded on Monday. A 4th qualified referral on the same Monday is silently skipped. Resets at midnight UTC.

7. Share Rate Limiting

Editable

Limits on how many times a user can share their referral link per day/month.

maxSharesPerDay
Type: Integer  |  Default: 100
Maximum times a referrer can share their code per day. Enforced by recordShare() which is called from the app before the system share sheet opens. Set to 0 to disable.
Example: 50 → user taps share 51 times in one day → 51st tap returns "Daily share limit reached (50)".
maxSharesPerMonth
Type: Integer  |  Default: 1000
Maximum times a referrer can share their code per calendar month. Same enforcement as daily limit.
Example: 500 → after 500 shares in a month, further shares are blocked.

8. Reward Reversal

Editable
autoReversalWindowDays
Type: Integer  |  Default: 30
Number of days after which a REWARDED referral is automatically reversed. A cron job runs every 24 hours. Points are deducted from the referrer's balance (partial deduction if insufficient balance, the remainder tracked as outstandingRecoveryPoints). Set to 0 to disable.
Example: 30 →
DateEvent
1 JanReward issued — referrer gets 50 points
15 JanReferrer spends 30 points (20 left)
31 JanCron runs: 31 Jan - 30 days = 1 Jan ≤ 1 Jan → REVERSED
20 points deducted (20 left), 30 marked as outstanding recovery
Status changes from REWARDED → REVERSED.

9. Share Message

Editable
shareMessageTemplate
Type: String  |  Default: "Join FreshPickKat using my referral code {CODE}. Get ₹50 OFF on your first order!"
The message template used when sharing via the Share sheet. {CODE} is automatically replaced with the user's actual referral code.
Example: Template "Use my code {CODE} and get ₹50 off!" → Shared message: "Use my code FPKAB12 and get ₹50 off!"

10. System Settings (Read Only)

Read Only

These fields are controlled by the system. The admin can view the current values but cannot change them. They use their database defaults if not explicitly set.

Fraud Scoring

enableFraudScoring
Type: Boolean  |  Default: true
Controls whether soft scoring rules (address matching, payment contact, velocity) are evaluated. When false, all soft rules are skipped and return score 0. Hard reject rules (same UID, same phone, already rewarded) always run regardless.
Example: false → Only hard reject checks run. If no hard reject, the referral score is 0 → AUTO_APPROVE.
autoApproveThreshold
Type: Integer  |  Default: 40
If total fraud score is less than this value → AUTO_APPROVE. The reward is processed immediately.
Example: 40 → Score 0-39 = auto-approve. Referral A scores 25 → AUTO_APPROVE → reward processed.
manualReviewThreshold
Type: Integer  |  Default: 69
If total fraud score is greater than this value → high-risk zone. Combined with enableRewardHold to decide between hold vs manual review.
Example: 69 → Score 70+ is high risk. Score 50 is still in the 40-69 range → MANUAL_REVIEW (if enableRewardHold = false) or AUTO_HOLD (if enableRewardHold = true).
autoRejectThreshold
Type: Integer  |  Default: 90
If total fraud score is greater than or equal to this value → AUTO_REJECT (if enableAutoReject = true) or AUTO_HOLD (if enableAutoReject = false).
Example: 90 → Score 95 → AUTO_REJECT. Referral is marked REJECTED with fraud notes.
enableRewardHold
Type: Boolean  |  Default: true
When true, referrals with fraud score above manualReviewThreshold (70+) are placed in REWARD_HELD status with a hold timer (holdDurationHours). After the hold expires, the cron job releases the reward. When false, such referrals go to PENDING_REVIEW instead, requiring manual admin approval.
Example: true → Score 78 → REWARD_HELD for 72 hours → auto-release. false → Score 78 → PENDING_REVIEW → admin must approve.
holdDurationHours
Type: Integer  |  Default: 72
How many hours a REWARD_HELD referral stays on hold before the cron job automatically releases it. Only used when enableRewardHold = true.
Example: 72 → 3 days hold. Held at 1 Jan 10:00 UTC → released at 4 Jan 10:00 UTC.
enableAutoReject
Type: Boolean  |  Default: true
When true, fraud score ≥ autoRejectThreshold (90+) results in AUTO_REJECT. When false, even 90+ scores are downgraded to AUTO_HOLD instead.
Example: false → Referral with score 95 is placed in REWARD_HELD instead of being rejected. Useful when you want to review all high-score referrals manually via the hold mechanism.

Capacity

maxPendingReferrals
Type: Integer  |  Default: 50
Maximum number of pending referrals (status: SIGNED_UP, PENDING_REVIEW, or REWARD_HELD) a single referrer can have at any time. If the referrer already has this many pending referrals, a new invitee trying to use their code will get an error.
Example: 10 → Referrer A has 10 pending referrals. Invitee #11 tries to use A's code → error: "Referrer has too many pending referrals".

Velocity Rule

referralVelocityScore
Type: Integer  |  Default: 30
Fraud points added per extra referral beyond the velocity threshold. Used to detect a single referrer creating many referrals in a short time.
velocityTimeWindowHours
Type: Integer  |  Default: 24
The time window (in hours) to look back when counting recent referrals for velocity checks.
velocityThreshold
Type: Integer  |  Default: 3
The number of referrals allowed within the time window before penalties apply.
Combined Example: velocityScore = 30, window = 24h, threshold = 3
Referrer A creates 5 referrals in 24 hours:
extra = 5 - 3 = 2
velocity score = 30 × 2 = 60
This adds 60 points to the total fraud score, potentially pushing it into hold/reject territory.

Terms & Conditions

termsText
Type: String?  |  Default: null
Text displayed in the Invite & Earn screen for referral program terms. Shown above the acceptance checkbox. If null, the terms section is hidden.
Example: "Referral points are valid for 90 days. Referral rewards may be reversed if fraud is detected." → displayed as terms on the Invite & Earn screen.

Score Decision Matrix

After all rules are evaluated, the total fraud score determines what happens:

Score Range enableAutoReject enableRewardHold Status What Happens
0–39 — — REWARDED Auto-approved immediately
40–69 — true REWARD_HELD Auto-released after holdDurationHours
40–69 — false PENDING_REVIEW Admin must approve manually
70–89 — true REWARD_HELD Auto-released after holdDurationHours
70–89 — false PENDING_REVIEW Admin must approve manually
90+ true — REJECTED Auto-rejected, no reward
90+ false — REWARD_HELD Downgraded to hold instead of reject
Hard Reject true — REJECTED Same UID/phone/already rewarded
💡 Tip: For a trust-based program, set enableFraudProtection = false to bypass all scoring. For strict fraud prevention, enable everything and set thresholds according to your risk appetite.

Scoring Flow Diagram

checkOrderForReward()
  │
  ├── isEnabled = false? → return (disabled)
  ├── minimumActualPaymentForQualification check? → fail → return
  ├── rewardTriggerStatus check? → fail → return
  ├── maxRewardedPerMonth cap? → hit → return
  ├── maxRewardedPerDay cap? → hit → return
  ├── Self-referral? → REJECTED
  │
  └── enableFraudProtection?
        │
        ├── true →
        │     ├── Hard Reject Rules (always):
        │     │   ├── Same UID? → AUTO_REJECT (score 999)
        │     │   ├── Same Phone? → AUTO_REJECT (score 999)
        │     │   └── Already Rewarded? → AUTO_REJECT (score 999)
        │     │
        │     └── Soft Scoring (if enableFraudScoring):
          │           ├── Same Address → +20/40/70
          │           ├── Same Payment Contact → +30
          │           ├── Same Payer Name → +20
          │           └── Referral Velocity → +score × extra
        │
        └── false → skip fraud, seedha _processReward()
